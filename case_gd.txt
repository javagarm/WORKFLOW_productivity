QUESTION 7: INSIGHT GENERATION
--------------------------------------------------------------------------------

"If I give you 1 year of hospital claims data AND pharmacy purchase 
data combined, what are the top 5 insights or patterns you would 
look for?"

POSSIBLE ANSWERS:

1. Duplicate claims - Same patient, same procedure, same date, 
   different claim IDs (Direct fraud detection)

2. Doctor-pharmacy nexus - One doctor always prescribing expensive 
   branded drugs from one specific pharmacy (Kickback fraud)

3. Billing vs market rate - Hospital charging Rs.5000 for a test 
   that costs Rs.500 everywhere else (Overbilling detection)

4. Ghost patients - Claims for patients who never visited, 
   cross-check admission records vs pharmacy purchases (Fake claims)

5. Chronic patient patterns - Patients buying diabetes medicine 
   monthly but hospital claims show surgery every quarter 
   (Inconsistency = red flag)

6. Seasonal spikes - Sudden increase in dengue claims in a 
   non-monsoon month in a specific hospital (Potential fabrication)

7. Prescription without diagnosis - Pharmacy shows expensive drug 
   purchase but no corresponding hospital diagnosis (Data mismatch)

WHAT TO OBSERVE: Creativity and depth - do they think like a detective 
or just a report generator?

QUESTION 8: FRAUD SCENARIO - CRITICAL THINKING
--------------------------------------------------------------------------------

"A hospital in a small town submits 500 knee replacement surgery 
claims in one month. The national average for a hospital that size 
is 20 per month. Is this definitely fraud? How would you investigate?"

POSSIBLE ANSWERS:

NOT necessarily fraud - could be legitimate if:
- Hospital is a specialty orthopedic center
- They ran a free/subsidized surgery camp
- They are the only hospital in a large rural area
- Renowned surgeon joined recently attracting patients

Investigation steps:
- Compare with previous months - sudden spike or gradual growth?
- Check patient demographics - all from same area or suspiciously 
  spread across states?
- Verify patient identities - Aadhaar/ID cross-check
- Check if same patients had knee replacement claimed before 
  (you cannot replace the same knee twice!)
- Look at average cost per surgery vs national benchmark
- Check doctor-to-surgery ratio - can 2 doctors physically do 
  500 surgeries in 30 days?
- Cross-reference pharmacy data - were post-surgery medicines 
  purchased?
- Check if patients had pre-surgery tests done (X-ray, blood work)

WHAT TO OBSERVE: Do they jump to "ITS FRAUD!" or think critically 
and consider both sides?

QUESTION 10: SQL SCENARIO
--------------------------------------------------------------------------------

"I have a table called CLAIMS with columns: claim_id, patient_id, 
hospital_id, procedure_code, claim_amount, claim_date, status. 
How would you write a query to find hospitals that submitted more 
than 100 claims in a single day?"

POSSIBLE ANSWERS:

Basic correct answer:
SELECT hospital_id, claim_date, COUNT(*) as claim_count
FROM CLAIMS
GROUP BY hospital_id, claim_date
HAVING COUNT(*) > 100
ORDER BY claim_count DESC;

Better answer adds:
- JOIN with hospital master table to get hospital name and location
- Filter by status = 'APPROVED' or 'PENDING'
- Add date range filter for specific analysis period
- Compare against average daily claims for that hospital

BONUS if they mention:
- Creating a view or temp table for reuse
- Adding percentage above average calculation
- Window functions for trend analysis

WHAT TO OBSERVE: SQL fundamentals, logical thinking, ability to 
go beyond basic query

QUESTION 12: STATISTICAL THINKING
--------------------------------------------------------------------------------

"If the average hospital claim amount in Chennai is Rs.25,000 and 
one hospital consistently submits claims averaging Rs.75,000, what 
statistical methods would you use to determine if this is an outlier 
or genuinely different?"

POSSIBLE ANSWERS:

Basic methods:
- Z-score calculation - how many standard deviations from mean
- IQR method (Interquartile Range) - Q1, Q3, identify outliers
- Box plot visualization to see distribution

Better answers:
- Compare within same hospital category (multi-specialty vs single)
- Compare within same procedure types (not overall average)
- Use percentile ranking - where does this hospital fall?
- T-test or Mann-Whitney test to check statistical significance
- Look at the distribution - is it normal or skewed?

Advanced answers:
- Regression analysis controlling for hospital size, specialization, 
  patient severity
- Clustering hospitals into peer groups first, then compare
- Time series analysis - has it always been high or sudden change?
- Benford's Law analysis on claim amounts for digit pattern fraud

Context they should consider:
- Hospital might be a premium/corporate hospital (legitimately higher)
- Case mix might be different (more complex surgeries)
- Location cost differences within the same city

WHAT TO OBSERVE: Statistical knowledge depth, ability to think beyond 
simple average comparison

QUESTION 13: REAL-TIME SCENARIO
--------------------------------------------------------------------------------

"Right now, most fraud is detected AFTER payment is made. If you 
were asked to build a system that detects fraud BEFORE payment, 
what would you design?"

POSSIBLE ANSWERS:

System components:
- Rule-based engine for known fraud patterns
  * Duplicate claim check
  * Amount exceeds threshold for procedure
  * Provider not registered/blacklisted
  * Patient already has active claim elsewhere

- Machine Learning model for unknown patterns
  * Trained on historical fraud cases
  * Anomaly detection for unusual patterns
  * Risk scoring for each claim (0-100)

- Real-time data checks
  * Verify patient identity instantly (Aadhaar API)
  * Check provider license status
  * Cross-reference with pharmacy data
  * Geo-location verification

- Workflow
  * Low risk (score 0-30) -> Auto approve
  * Medium risk (score 31-70) -> Flag for review
  * High risk (score 71-100) -> Hold payment, investigate

- Feedback loop
  * Investigators confirm or dismiss flags
  * Model retrains with new confirmed fraud cases
  * Rules updated based on new patterns

WHAT TO OBSERVE: System thinking, understanding of ML basics, 
practical implementation awareness

QUESTION 18: BUSINESS IMPACT CALCULATION
--------------------------------------------------------------------------------

"Your fraud detection model flags 10,000 claims per month. After 
investigation, 6,000 turn out to be actual fraud (true positives) 
and 4,000 are legitimate claims wrongly flagged (false positives). 
Each investigation costs Rs.500. Each caught fraud saves Rs.50,000. 
Each false positive causes a 2-day payment delay to the hospital. 
Is this model good? How would you improve it?"

POSSIBLE ANSWERS:

Current Performance:
- Precision = 6000/10000 = 60% (not great)
- Monthly fraud caught = 6000 x Rs.50,000 = Rs.30 crore saved
- Investigation cost = 10000 x Rs.500 = Rs.5 lakh
- Net savings = Rs.30 crore - Rs.5 lakh = ~Rs.29.95 crore
- BUT 4000 hospitals face delayed payments = relationship damage

Assessment:
- Financially the model is very profitable
- But 40% false positive rate is too high
- Hospitals getting wrongly flagged will lose trust
- Could lead to hospitals leaving the network

How to improve:
